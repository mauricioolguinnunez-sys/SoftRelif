#################### 1. ALCANCE Y ARQUITECTURA ####################

SoftRelief usa una arquitectura híbrida de almacenamiento:

- MySQL (softrelief): identidad, acceso, roles, permisos, estados de cuenta,
  preferencias visuales y bitácora de auditoría. Es la parte formal y relacional.
- MongoDB (wellbeing): documentos históricos por id_usuario con check-ins
  emocionales, música (favoritos, pistas), microdescansos y resúmenes de bienestar.

El presente documento cubre únicamente el componente MySQL.


#################### 2. RECOMENDACIONES (CORRECCIONES RESPECTO A LA DOCUMENTACIÓN ANTERIOR) ####################

1. ESTADOS DE CUENTA: La documentación anterior declaraba 4 estados
   (Activo, Suspendido, Bloqueado, Inactivo). La implementación real solo usa 2:
   activa y restringida. Actualizar el enunciado a estos 2 únicos estados.

2. CAMPOS INEXISTENTES EN USUARIO: ap_paterno, ap_materno, fecha_ultimo_acceso y
   password_hash NO existen en la tabla real. La tabla usa un solo campo nombre
   (VARCHAR 120) y la columna de contraseña se llama contrasena (VARCHAR 255).

3. PREFERENCIA_VISUAL: El diccionario anterior decía tema_visual (VARCHAR).
   La implementación usa id_tema (FK hacia TEMA) + tamano_fuente +
   modo_visualizacion + idioma. No existe la columna tema_visual.

4. PERMISOS: La documentación omitía marcar_seguimiento (RF-21) y documentaba
   sugerir_musica como permiso del especialista (existe en el código actual).
   El permiso consultar_historial_bienestar NO está asignado a superuser en la
   implementación real (solo al especialista). Total real: 16 permisos.

5. CONTRASEÑAS: La implementación inserta los usuarios base con hash SHA-256
   (utils/password_utils.py), NO en texto plano. Documentar que los valores
   'admin123' y 'especialista123' son contraseñas de prueba que se almacenan
   cifradas. Recomendación futura: migrar a bcrypt/Argon2.

6. BITACORA_CUENTA: El campo id_admin almacena al actor que ejecutó la acción
   (puede ser superuser o especialista). Aunque funciona, se recomienda
   renombrarlo a id_actor para reflejar mejor su papel en el MER/MR.

7. BUG CORREGIDO (18/03/2026): models/user_model.py, método delete_user (línea 1168)
   ejecutaba "DELETE FROM usuarios" (tabla incorrecta, no existe). Ya corregido a
   "DELETE FROM usuario" y ahora también elimina la preferencia_visual asociada
   para no dejar registros huérfanos (igual que views/superuser_view.py).

8. TIPOS REALES: fecha_registro es DATE (no DATETIME). permiso.nombre es
   VARCHAR(80) (no 100). tema.nombre es VARCHAR(30) (no 50). bitacora.accion
   es VARCHAR(80) y bitacora.descripcion es VARCHAR(255) (no TEXT).

9. ATRIBUTOS PARA EL MER (los que SÍ se pueden demostrar en el modelo real):
   - Simple: nombre, correo, contrasena, fecha_registro.
   - Derivado: antiguedad_cuenta (calculable desde fecha_registro).
   - Opcional: id_admin e id_usuario en bitacora_cuenta (NULL permitido).
   - Asociado a relación: las columnas id_rol / id_permiso de rol_permiso.
   - No documentar apellidos compuestos ni atributos multivaluados, porque la
     implementación no los tiene. No inventar atributos solo para la rúbrica.


#################### 3. MODELO ENTIDAD-RELACIÓN (MER) ####################

ENTIDADES Y ATRIBUTOS (exactos a la implementación):

ESTADO_CUENTA (id_estado, nombre, descripcion)
ROL          (id_rol, nombre, descripcion)
PERMISO      (id_permiso, nombre, descripcion)
TEMA         (id_tema, nombre, descripcion)
PREFERENCIA_VISUAL (id_preferencia, id_tema, tamano_fuente, modo_visualizacion, idioma)
USUARIO      (id_usuario, nombre, correo, contrasena, fecha_registro,
              id_rol, id_estado, id_preferencia)
BITACORA_CUENTA (id_bitacora, id_admin, id_usuario, accion, descripcion, fecha_evento)

RELACIONES Y CARDINALIDADES:
- ROL contiene PERMISO            : N:M (se resuelve con ROL_PERMISO)
- ROL clasifica USUARIO           : 1:N
- ESTADO_CUENTA asigna USUARIO    : 1:N
- TEMA define PREFERENCIA_VISUAL  : 1:N
- USUARIO posee PREFERENCIA_VISUAL: 1:1 (id_preferencia UNIQUE en usuario)
- USUARIO realiza BITACORA_CUENTA : 1:N (papel actor, id_admin)
- USUARIO es_afectado_por BITACORA_CUENTA: 1:N (papel afectado, id_usuario)

TOTAL: 8 entidades, 7 relaciones (1 N:M, 2 1:N de bitácora, 1 1:1, 3 1:N).

PERMISO(
  id_permiso   INT PK AUTO_INCREMENT,
  nombre       VARCHAR(80)  NOT NULL UNIQUE,

)

ROL_PERMISO(
  id_rol       INT PK, FK -> ROL(id_rol)      ON DELETE CASCADE ON UPDATE CASCADE,
  id_permiso   INT PK, FK -> PERMISO(id_permiso) ON DELETE CASCADE ON UPDATE CASCADE
)

TEMA(
  id_tema      INT PK AUTO_INCREMENT,
  nombre       VARCHAR(30)  NOT NULL UNIQUE,
  descripcion  VARCHAR(255) NOT NULL
)

PREFERENCIA_VISUAL(
  id_preferencia     INT PK AUTO_INCREMENT,
  id_tema            INT NOT NULL FK -> TEMA(id_tema) ON DELETE RESTRICT ON UPDATE CASCADE,
  tamano_fuente      VARCHAR(30) NOT NULL DEFAULT 'normal',
  modo_visualizacion VARCHAR(30) NOT NULL DEFAULT 'estandar',
  idioma             VARCHAR(10) NOT NULL DEFAULT 'es'
)

USUARIO(
  id_usuario     INT PK AUTO_INCREMENT,
  nombre         VARCHAR(120) NOT NULL,
  correo         VARCHAR(150) NOT NULL UNIQUE,
  contrasena     VARCHAR(255) NOT NULL,   -- almacena hash SHA-256
  fecha_registro DATE         NOT NULL,
  id_rol         INT NOT NULL FK -> ROL(id_rol)             ON DELETE RESTRICT ON UPDATE CASCADE,
  id_estado      INT NOT NULL FK -> ESTADO_CUENTA(id_estado) ON DELETE RESTRICT ON UPDATE CASCADE,
  id_preferencia INT NOT NULL UNIQUE FK -> PREFERENCIA_VISUAL(id_preferencia)
                    ON DELETE RESTRICT ON UPDATE CASCADE
)

BITACORA_CUENTA(
  id_bitacora  INT PK AUTO_INCREMENT,
  id_admin     INT NULL FK -> USUARIO(id_usuario) ON DELETE SET NULL ON UPDATE CASCADE,
  id_usuario   INT NULL FK -> USUARIO(id_usuario) ON DELETE SET NULL ON UPDATE CASCADE,
  accion       VARCHAR(80)  NOT NULL,
  descripcion  VARCHAR(255) NOT NULL,
  fecha_evento DATETIME     NOT NULL
)


#################### 5. DICCIONARIO DE DATOS ####################

ESTADO_CUENTA
  id_estado    | INT         | PK       | Identificador del estado.

  descripcion  | VARCHAR(255)| -        | Descripción del estado de la cuenta.

ROL
  id_rol       | INT         | PK       | Identificador del rol.
  nombre       | VARCHAR(50) | UNIQUE   | Nombre del rol (usuario, especialista, superuser).
  descripcion  | VARCHAR(255)| -        | Descripción del rol y sus funciones.

PERMISO
  id_permiso   | INT         | PK       | Identificador del permiso.
  nombre       | VARCHAR(80) | UNIQUE   | Nombre del permiso.
  descripcion  | VARCHAR(255)| -        | Descripción del permiso.

ROL_PERMISO
  id_rol       | INT         | PK, FK   | Rol al que se asigna el permiso.
  id_permiso   | INT         | PK, FK   | Permiso asignado al rol.

TEMA
  id_tema      | INT         | PK       | Identificador del tema.
  nombre       | VARCHAR(30) | UNIQUE   | Nombre del tema (light, dark).
  descripcion  | VARCHAR(255)| -        | Descripción del tema visual.

PREFERENCIA_VISUAL

  id_tema            | INT          | FK       | Tema visual seleccionado (light/dark).
  tamano_fuente      | VARCHAR(30)  | -        | Tamaño de fuente (normal).
  modo_visualizacion | VARCHAR(30)  | -        | Modo de visualización (estandar).
  idioma             | VARCHAR(10)  | -        | Idioma de la interfaz (es, en).

USUARIO
  id_usuario     | INT          | PK       | Identificador del usuario.
  nombre         | VARCHAR(120) | -        | Nombre completo del usuario.
  correo         | VARCHAR(150) | UNIQUE   | Correo electrónico del usuario.
  contrasena     | VARCHAR(255) | -        | Contraseña cifrada (hash SHA-256).
  fecha_registro | DATE         | -        | Fecha en que se registró el usuario.
  id_rol         | INT          | FK       | Rol asignado al usuario.
  id_estado      | INT          | FK       | Estado actual de la cuenta.
  id_preferencia | INT          | FK,UNIQUE| Preferencia visual del usuario.

BITACORA_CUENTA
  id_bitacora  | INT          | PK       | Identificador del registro de bitácora.
  id_admin     | INT          | FK, NULL | Actor (superuser o especialista) que ejecutó la acción.
  id_usuario   | INT          | FK, NULL | Usuario afectado por la acción.
  accion       | VARCHAR(80)  | -        | Acción realizada (asignar_recomendacion, cargar_recurso, sugerir_musica, marcar_seguimiento, eliminar, activa, restringida).
  descripcion  | VARCHAR(255) | -        | Descripción detallada de la acción.

-- Base de datos
CREATE DATABASE IF NOT EXISTS softrelief
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;

USE softrelief;

-- =====================================================
-- TABLA: estado_cuenta
-- =====================================================
CREATE TABLE IF NOT EXISTS estado_cuenta (
   id_estado INT AUTO_INCREMENT PRIMARY KEY,
   nombre VARCHAR(50) NOT NULL UNIQUE,
   descripcion VARCHAR(255) NOT NULL
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_unicode_ci;

-- =====================================================
-- TABLA: rol
-- =====================================================
CREATE TABLE IF NOT EXISTS rol (
   id_rol INT AUTO_INCREMENT PRIMARY KEY,
   nombre VARCHAR(50) NOT NULL UNIQUE,
   descripcion VARCHAR(255) NOT NULL
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_unicode_ci;

-- =====================================================
-- TABLA: permiso
-- =====================================================
CREATE TABLE IF NOT EXISTS permiso (
   id_permiso INT AUTO_INCREMENT PRIMARY KEY,
   nombre VARCHAR(80) NOT NULL UNIQUE,
   descripcion VARCHAR(255) NOT NULL
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_unicode_ci;

-- =====================================================
-- TABLA: rol_permiso (relación N:M rol-permiso)
-- =====================================================
CREATE TABLE IF NOT EXISTS rol_permiso (
  id_rol INT NOT NULL,
  id_permiso INT NOT NULL,

  PRIMARY KEY (id_rol, id_permiso),

  CONSTRAINT fk_rol_permiso_rol
    FOREIGN KEY (id_rol)
    REFERENCES rol(id_rol)
    ON UPDATE CASCADE
    ON DELETE CASCADE,

  CONSTRAINT fk_rol_permiso_permiso
    FOREIGN KEY (id_permiso)
    REFERENCES permiso(id_permiso)
    ON UPDATE CASCADE
    ON DELETE CASCADE
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_unicode_ci;

-- =====================================================
-- TABLA: tema
-- =====================================================
CREATE TABLE IF NOT EXISTS tema (
   id_tema INT AUTO_INCREMENT PRIMARY KEY,
   nombre VARCHAR(30) NOT NULL UNIQUE,
   descripcion VARCHAR(255) NOT NULL
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_unicode_ci;

-- =====================================================
-- TABLA: preferencia_visual
-- =====================================================
CREATE TABLE IF NOT EXISTS preferencia_visual (
  id_preferencia INT AUTO_INCREMENT PRIMARY KEY,
  id_tema INT NOT NULL,
  tamano_fuente VARCHAR(30) NOT NULL DEFAULT 'normal',
  modo_visualizacion VARCHAR(30) NOT NULL DEFAULT 'estandar',
  idioma VARCHAR(10) NOT NULL DEFAULT 'es',

  CONSTRAINT fk_preferencia_tema
    FOREIGN KEY (id_tema)
    REFERENCES tema(id_tema)
    ON UPDATE CASCADE
    ON DELETE RESTRICT
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_unicode_ci;

-- =====================================================
-- TABLA: usuario
-- =====================================================
CREATE TABLE IF NOT EXISTS usuario (
  id_usuario INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(120) NOT NULL,
  correo VARCHAR(150) NOT NULL UNIQUE,
  contrasena VARCHAR(255) NOT NULL,
  fecha_registro DATE NOT NULL,
  id_rol INT NOT NULL,
  id_estado INT NOT NULL,
  id_preferencia INT NOT NULL UNIQUE,

  CONSTRAINT fk_usuario_rol
    FOREIGN KEY (id_rol)
    REFERENCES rol(id_rol)
    ON UPDATE CASCADE
    ON DELETE RESTRICT,

  CONSTRAINT fk_usuario_estado
    FOREIGN KEY (id_estado)
    REFERENCES estado_cuenta(id_estado)
    ON UPDATE CASCADE
    ON DELETE RESTRICT,

  CONSTRAINT fk_usuario_preferencia
    FOREIGN KEY (id_preferencia)
    REFERENCES preferencia_visual(id_preferencia)
    ON UPDATE CASCADE
    ON DELETE RESTRICT
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_unicode_ci;

-- =====================================================
-- TABLA: bitacora_cuenta
-- =====================================================
CREATE TABLE IF NOT EXISTS bitacora_cuenta (
  id_bitacora INT AUTO_INCREMENT PRIMARY KEY,
  id_admin INT NULL,
  id_usuario INT NULL,
  accion VARCHAR(80) NOT NULL,
  descripcion VARCHAR(255) NOT NULL,
  fecha_evento DATETIME NOT NULL,

  CONSTRAINT fk_bitacora_admin
    FOREIGN KEY (id_admin)
    REFERENCES usuario(id_usuario)
    ON UPDATE CASCADE
    ON DELETE SET NULL,

  CONSTRAINT fk_bitacora_usuario
    FOREIGN KEY (id_usuario)
    REFERENCES usuario(id_usuario)
    ON UPDATE CASCADE
    ON DELETE SET NULL
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_unicode_ci;

-- Q-AUTH-01: Login por correo o nombre de usuario (get_user_by_username_or_email)
SELECT
    u.id_usuario,
    u.nombre,
    u.correo,
    u.contrasena AS password_hash,
    u.fecha_registro,
    r.nombre AS rol,
    ec.nombre AS estado,
    pv.id_preferencia,
    t.nombre AS tema_visual,
    pv.tamano_fuente,
    pv.modo_visualizacion,
    COALESCE(pv.idioma, 'es') AS idioma
FROM usuario u
LEFT JOIN rol r ON u.id_rol = r.id_rol

-- Q-USR-03: Usuarios comunes para el panel del especialista

    u.nombre,
    u.correo,
    u.correo AS usuario,
    u.fecha_registro,
    COALESCE(r.nombre, 'sin_rol') AS rol,
    COALESCE(ec.nombre, 'sin_estado') AS estado,
    pv.id_preferencia,

    COALESCE(pv.modo_visualizacion, 'estandar') AS modo_visualizacion,
    COALESCE(pv.idioma, 'es') AS idioma,
    COUNT(b.id_bitacora) AS acciones_especialista,
    MAX(
        CASE
            WHEN b.accion = 'asignar_recomendacion'
            THEN b.fecha_evento
            ELSE NULL
        END
    ) AS ultima_recomendacion

LEFT JOIN estado_cuenta ec ON u.id_estado = ec.id_estado
LEFT JOIN preferencia_visual pv ON u.id_preferencia = pv.id_preferencia
LEFT JOIN tema t ON pv.id_tema = t.id_tema
LEFT JOIN bitacora_cuenta b
    ON b.id_usuario = u.id_usuario
    AND b.id_admin = %s
    AND b.accion IN ('asignar_recomendacion', 'cargar_recurso')
WHERE r.nombre = 'usuario'
GROUP BY
    u.id_usuario, u.nombre, u.correo, u.fecha_registro,
    r.nombre, ec.nombre, pv.id_preferencia, t.nombre,
    pv.tamano_fuente, pv.modo_visualizacion, pv.idioma
ORDER BY u.id_usuario DESC;
